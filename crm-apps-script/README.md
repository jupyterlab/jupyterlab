# CRM Console — نظام إدارة العملاء والتحصيل (Google Sheets + Apps Script)

تطبيق ويب يعمل على Google Sheets كقاعدة بيانات، لعرض أرصدة العملاء والفواتير المسددة والمتأخرات من بيانات Dynamics 365.

## الملفات

| الملف | الوظيفة |
|---|---|
| `Code.gs` | الخادم: الجداول، تسجيل الدخول، الصلاحيات، التقارير، الاستيراد |
| `Index.html` | الصفحة الرئيسية |
| `Styles.html` | التنسيقات (نفس ألوان وتصميم الملف المرجعي + دعم العربية والجوال) |
| `Script.html` | واجهة المستخدم وكل الصفحات |
| `appsscript.json` | إعدادات المشروع |

## خطوات التشغيل (5 دقائق)

1. أنشئ Google Sheet جديد ← من القائمة **Extensions ← Apps Script**.
2. انسخ محتوى `Code.gs` في ملف `Code.gs`.
3. أنشئ ملفات HTML بالأسماء **Index** و **Styles** و **Script** (بدون `.html`) والصق محتوى كل ملف.
4. (اختياري) من Project Settings فعّل "Show appsscript.json" والصق المحتوى، وعدّل `timeZone`.
5. من أعلى المحرر اختر الدالة `setup` واضغط **Run** ووافق على الصلاحيات.
   - لتجربة النظام ببيانات وهمية شغّل `loadDemoData` بدلاً منها.
6. **Deploy ← New deployment ← Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone** (أو Anyone in your organization)
7. افتح الرابط وسجّل الدخول: **admin / admin123** ثم غيّر كلمة المرور فوراً من صفحة المستخدمين.
   - كل فتح جديد للرابط (تبويب جديد) يطلب كلمة المرور، والجلسة تنتهي بعد مدة خمول (60 دقيقة افتراضياً، تُضبط من الإعدادات).
   - عند أول استخدام لإرسال البريد أو رابط Drive سيطلب Google موافقة إضافية (Gmail / Drive): وافق ثم انشر نسخة جديدة.

> بعد أي تعديل على الكود: Deploy ← Manage deployments ← Edit ← Version: New version.
>
> **مهم:** استبدل `Code.gs` وملفات HTML معاً في كل تحديث. إذا اختلفت النسخ يظهر شريط أصفر «ملف Code.gs غير محدّث» بدلاً من أخطاء مثل `... is not a function`.

## الجداول (Sheets)

يتم إنشاؤها تلقائياً بـ `setup()`. أسماء الأعمدة مطابقة لتصدير Dynamics 365، فيمكن اللصق مباشرة تحتها.

- **Customers**: Customer account, Name, Customer group, Currency, Contact Number, Email, Address, Status, Created date and time + (Contact Person, City, Country, Tax Number, Credit Limit, Payment Terms Days, Collector, Notes)
- **Transactions**: Voucher, Transaction type, Customer account, Date, Description, Due Date, Amount in transaction currency, Currency, Exchange rate, Credit in local currency, Debit in local currency, user add, created_by_user_id, created_by_name, created_at, updated_by_name, updated_at, is_deleted + (posting_status, posted_by, posted_at, row_id)
- **CustomerGroups**: GroupId, GroupName
- **Users**: المستخدمون والصلاحيات (كلمات المرور مشفّرة SHA-256)
- **FollowUps**: سجل متابعات التحصيل والوعود بالسداد
- **Currencies**: رمز العملة، الاسم، السعر مقابل عملة التقارير (يُنشأ تلقائياً عند أول استخدام)
- **Settings**: اسم التطبيق، اسم الشركة، العملة المحلية، عملة التقارير، أساس التحويل

## طريقة إدخال بيانات Dynamics 365

- **الأسهل:** صفحة **استيراد البيانات** ← اختر الجدول ← ارفع ملف Excel/CSV ← استيراد.
  - المطابقة تتم بأسماء الأعمدة تلقائياً.
  - "تحديث الموجود وإضافة الجديد" مناسب للتحديث الدوري للعملاء.
  - الحركات المستوردة تعتبر **مرحّلة**.
- **أو:** الصق البيانات مباشرة في الشيت تحت العناوين (الأعمدة الإضافية تتملأ تلقائياً).
- لربط العميل بمسؤول التحصيل: ضع **اسم مستخدم** المسؤول في عمود `Collector`.

## الصفحات

| الصفحة | المحتوى |
|---|---|
| لوحة التحكم | إجمالي العملاء، الأرصدة، المتأخرات، المحصل هذا الشهر، رسم الفواتير مقابل التحصيل، أعمار الديون، أعلى العملاء |
| العملاء | بحث وفلترة وإضافة/تعديل/حذف + بطاقة العميل (كشف حساب برصيد تراكمي ومتابعات) |
| حركات العملاء | الفواتير والدفعات، إضافة يدوية كمسودة ثم **ترحيل** |
| مجموعات العملاء | إدارة المجموعات |
| سندات التحصيل | تسجيل تحصيل نقدي / شيك / تحويل بنكي **مربوط بالفاتورة**، طباعة سند قبض، إجماليات حسب طريقة التحصيل |
| كشف حساب العميل | كشف رسمي A4 (رصيد افتتاحي، حركات برصيد تراكمي، أعمار الديون، الفواتير المفتوحة، بيانات التحويل البنكي)، إرسال بالبريد (PDF مرفق) أو واتساب |
| الرسائل والإشعارات | رسائل بين المستخدمين (لشخص أو أكثر أو للكل) مع ردود وربط بعميل، وتنبيهات النظام: سند تحصيل بانتظار الترحيل، ترحيل سندك، وعد سداد مستحق. متاحة لكل المستخدمين، مع جرس 🔔 وعدّاد يتحدث كل دقيقة |
| تقرير الأرصدة | رصيد افتتاحي + مدين + دائن + رصيد ختامي حسب الفترة والمجموعة والمسؤول |
| الفواتير المسددة | الفواتير المسددة بالكامل خلال الفترة، وهل سُددت في موعدها |
| تقرير المتأخرات | الفواتير المتجاوزة لتاريخ التحصيل، أيام التأخير، أعمار الديون (30/60/90/+90)، بحث برقم السند |
| تجاوز حد الائتمان | العملاء الذين تجاوز رصيدهم حد الائتمان بعملة العميل، مع نسبة الاستخدام والتجاوز والمتاح |
| متابعة المتأخرات | بطاقة لكل عميل متأخر + تسجيل اتصال/زيارة/وعد بالسداد + سجل المتابعات |
| لوحة فريق التحصيل | لكل مسؤول: الشركات، الأرصدة، المتأخرات، متوسط وأقصى أيام التأخير، المحصل هذا الشهر |
| تقرير التحصيل | المحصّل خلال الفترة حسب طريقة الدفع (نقدي/شيك/تحويل/أخرى) وحسب المحصّل، مع تبويب لتفاصيل السندات (رقم الشيك، البنك، المرجع). المحصّل = من سجّل السند، وللدفعات المستوردة = مسؤول العميل |
| أداء المحصلين | لكل مسؤول تحصيل: عدد الشركات، رصيد أول الفترة، فواتير الفترة، **المستحق**، **المحصّل**، الإشعارات الدائنة، **المتبقي**، نسبة التحصيل، المتأخرات وأقصى تأخير، مع قائمة شركات كل مسؤول |
| العملات وأسعار الصرف | تكويد العملات، اختيار عملة التقارير والعملة المحلية، وسعر كل عملة مقابل عملة التقارير |
| استيراد البيانات | رفع ملفات Excel/CSV (العملاء، الحركات، المجموعات، العملات) |
| المستخدمون والصلاحيات | إضافة مستخدم، الصفحات المسموحة، العمليات (إضافة/تعديل/حذف/ترحيل)، نطاق البيانات |

- كل القوائم والتقارير فيها **تصدير Excel (.xlsx)** بتنسيق الأرقام `#,##0.00` و**طباعة**.
- كل القوائم المنسدلة قابلة للبحث، والعميل يظهر بصيغة `الرقم — الاسم` في سطر واحد.
- كل الأرقام تظهر وتُكتب بفاصل الآلاف `000,000,000.00`.
- زر ☰ في الأعلى يُظهر/يُخفي القائمة الجانبية.

## الصلاحيات

- **الدور**: مدير النظام (كل شيء) أو مستخدم.
- **الصفحات**: تختار الصفحات التي تظهر للمستخدم.
- **العمليات**: إضافة / تعديل / حذف / ترحيل.
- **نطاق البيانات**: "عملاؤه فقط" ← مسؤول التحصيل يرى عملاءه فقط (حسب عمود Collector).
- الحركة **المرحّلة** لا يمكن تعديلها، ويمكن لمدير النظام فقط إلغاء ترحيلها.
- الصلاحيات تُفحص في الخادم، وليس فقط بإخفاء الأزرار.

## التحصيل وربطه بالفواتير

1. من **سندات التحصيل ← تسجيل تحصيل** (أو من بطاقة العميل / متابعة المتأخرات).
2. اختر العميل ← تظهر فواتيره المفتوحة ← حدّد الفاتورة/الفواتير والمبلغ لكل منها
   (أو اكتب المبلغ المحصّل ليُوزَّع تلقائياً على الأقدم).
3. اختر الطريقة: **نقدي** / **شيك** (رقم الشيك إلزامي + التاريخ + البنك) / **تحويل بنكي** (البنك + رقم الحوالة).
4. يُحفظ السند كمسودة (أو مرحّل مباشرة لمن لديه صلاحية الترحيل) ثم تظهر نافذة طباعة سند القبض.
- لا يُسمح بتحصيل أكثر من المتبقي على الفاتورة، والمبالغ المحجوزة في سندات مسودة تُخصم من المتبقي.
- **تعديل السند:** زر ✎ في سندات التحصيل (أو حركات العملاء) للسندات **غير المرحّلة** فقط: تغيير الطريقة والبيانات والفواتير والمبالغ، ويُعاد بناء الربط. السند المرحّل لا يُعدّل (يمكن للمدير إلغاء ترحيله أولاً).
- الربط محفوظ في شيت **Allocations**. الدفعات المستوردة من Dynamics بدون ربط تُسوّى تلقائياً على الأقدم.
- تقرير الفواتير المسددة يعرض سندات السداد وطريقة التحصيل لكل فاتورة.

## الطباعة

- كل الصفحات والتقارير: زر 🖨 ← اختر **رأسي** أو **أفقي** ← تُطبع على ورق **A4** بترويسة الشركة والفلاتر والإجماليات.
- تُطبع **كل** السجلات المفلترة (حتى 5,000 سجل) وليس الصفحة الظاهرة فقط، وكذلك تصدير Excel.
- **شعار الشركة:** من **المستخدمون ← إعدادات النظام ← رفع شعار** (PNG/JPG/SVG، يُصغّر تلقائياً). يظهر في القائمة وشاشة الدخول وكل المطبوعات وكشوف الحساب المرسلة.
- بيانات الترويسة (العنوان، الهاتف، البريد، بيانات التحويل البنكي، ملاحظة الكشف، كود دولة الواتساب) من **المستخدمون ← إعدادات النظام**.

## العملات

1. من صفحة **العملات وأسعار الصرف** حدّد:
   - **العملة المحلية**: عملة القيود في Dynamics (عمودا Debit/Credit in local currency).
   - **عملة التقارير**: العملة الافتراضية لكل التقارير ولوحة التحكم (سعرها دائماً = 1).
2. أضف كل عملة وسعرها = قيمة **1** منها بعملة التقارير.
   - مثال: عملة التقارير USD ← سعر DJF = 0.0056 ، سعر EUR = 1.08
3. عند تغيير عملة التقارير يُعاد حساب كل الأسعار تلقائياً.
4. أي عملة مستخدمة بدون سعر تظهر في تنبيه أصفر مع زر لإضافتها.
5. في كل تقرير يمكن اختيار **عملة العرض** مؤقتاً، ولوحة التحكم تعرض بطاقة لكل عملة عملاء بأرصدتهم بعملتهم.

> المستخدمون الحاليون (غير المدير) لا يرون الصفحتين الجديدتين إلا بعد إضافتهما لهم من صفحة المستخدمين.

## كيف تُحسب الأرقام

- **الرصيد الافتتاحي** في كل التقارير وكشف الحساب = حركات النوع **Opening balance** (أياً كان تاريخها) + صافي الحركات قبل بداية الفترة. حركات Opening balance لا تُحسب ضمن مدين/دائن الفترة ولا ضمن «الفواتير» في رسم لوحة التحكم.
- **عرض الأرقام**: لأقرب رقم صحيح بفاصل الآلاف، محاذاة لليمين بالعربية ولليسار بالإنجليزية (القيم المخزنة وملفات Excel تحتفظ بالكسور الكاملة؛ أسعار الصرف تظهر بكسورها).
- **الرصيد** = مجموع (Debit in local currency − Credit in local currency) للحركات المرحّلة وغير المحذوفة، ثم يُحوَّل لعملة العرض بالأسعار.
- المدين بالسالب في ملف Dynamics يُعامل كدائن (والعكس).
- **رصيد العميل** في صفحة الحركات = الرصيد التراكمي للعميل بالعملة المحلية بعد كل حركة مرحّلة.
- لوحة التحكم والتقارير تحسب حتى **تاريخ اليوم**؛ الحركات بتاريخ مستقبلي لا تدخل إلا عند وصول تاريخها.
- **المحصل** = الحركات الدائنة من نوع دفعة (Payment / سداد / تحصيل)، وإن لم توجد أنواع كهذه تُحسب كل الحركات الدائنة.
- **الفواتير المسددة / المتأخرات**: تتم تسوية الدفعات على الفواتير بالأقدم أولاً (FIFO).
- **تاريخ التحصيل المتوقع** = Due Date، وإذا كان فارغاً = التاريخ + أيام السداد للعميل.
- **أيام التأخير** = (تاريخ التقرير − تاريخ الاستحقاق).

## ملاحظات أداء

- مناسب حتى عشرات الآلاف من الحركات. البحث والترقيم يتمّان في الخادم.
- للبيانات الضخمة جداً (أكثر من 200 ألف صف) يُفضّل أرشفة السنوات القديمة في شيت منفصل وإدخال رصيد افتتاحي بحركة من نوع `Opening balance`.
